# 拾忆作品介绍

## 一、作品名称

**拾忆（Shiyi Memory）：个人工作记忆助手与桌面宠物**

拾忆是一款运行在 macOS 上的个人 AI 工作助手。它在用户授权后记录当前工作窗口中的可见文字，通过原文摘录、记忆检索和自然语言交互，帮助用户找回工作细节、恢复项目上下文、整理日报周报和管理定时事项。作品提供网页工作台和原生桌宠两种入口，两端共享会话、记忆和任务。

作品围绕“记录工作线索—查询核对—确认留存—回顾整理—继续行动”构建完整使用流程，解决工作信息分散、项目切换后难以接续、阶段总结缺少材料等问题。当前面向 Apple Silicon Mac、macOS 14 及以上的个人使用场景。

## 二、核心功能

### 1. 工作记录自动采集与时间线回溯

用户明确开启采集并完成系统授权后，应用默认每五秒尝试采集一次当前窗口画面，使用本机 OCR 识别文字，关联时间、应用和窗口信息。截图仅用于内存中的识别过程，不作为图片保存到磁盘。用户可以暂停采集、配置排除应用和窗口规则，锁屏或睡眠时自动挂起。

系统在调用大模型前进行文字去重，减少相同页面的重复记录，同时保护金额、日期、否定、错误和完成状态等重要变化。用户可以在工作时间线中搜索关键词、筛选项目、查看原文，也可以手动补充记录。

### 2. 有来源的记忆问答与项目上下文恢复

用户可以直接提问：“上次这个项目讨论了什么？”“昨天出现过哪些报错？”“今天有哪些可以回顾的记录？”助手按需检索有效工作材料，结合日期、项目和上下文组织回答，并提供来源入口供用户核对。

项目空间支持查看相关记录、恢复上下文、管理项目别名和合并重复项目。用户能够从已有资料重新接续工作。普通知识问答、写作建议和闲聊也可以直接进行，不要求事先存在相关个人记忆。

### 3. 长期记忆确认与日报、周报整理

自动采集内容以原文摘录保存；用户可以通过“编辑并长期留存”调整正文、日期和项目，预览后确认保存为独立记忆。原始文字默认保留三十天，未确认摘录随原文到期，独立确认记忆可以长期保留。

每日回顾和每周回顾按时间、项目组织材料。用户核对并选择确认内容后，点击生成报告草稿，再人工编辑、保存和导出。草稿与人工稿分别保存，后台生成不会覆盖人工编辑。屏幕中出现的计划或第三方文字，不会直接被当作用户完成的成果写入草稿。

### 4. 定时提醒与自然语言对象管理

用户可以通过表单或对话设置事项，明确日期、时间、时区和重复规则。提醒支持一次性、每天、周一至周五、每周指定星期，可以完成本次、延后十分钟，或暂停整个日程。电脑恢复运行后，系统合并补报错过的重复提醒。

助手还可以为待办、项目和记忆提出创建、修改、合并或删除操作。操作以卡片展示具体目标和修改内容，由用户确认后执行。批量删除使用一张固定目标清单，支持一次核对、一次确认。采集和自动整理不会自行创建待办。

### 5. 网页与桌宠共享交互及主动陪伴

网页提供完整的时间线、项目、回顾和管理界面；桌宠提供随手可用的聊天与提醒入口。两端共享消息、运行状态和操作卡片，用户可以接续同一段对话。关闭桌宠聊天窗口后，后台任务仍可继续。

桌宠支持拖动定位、自定义 PNG 形象和轻微动效，也可以按用户设置进行闲聊、工作鼓励、天气关心和休息邀请。主动气泡无声音、不抢焦点，遇到全屏、锁屏、聊天、节能或安静时段会跳过。用户可以调整频率、风格和话题，通过明确反馈表达喜好，也可以选择“今天先安静”。

### 6. 可选本机编程与联网工具

用户绑定本机项目目录并启用编程后，内置 Pi Coding Agent 可以读取代码、修改文件、执行命令和运行测试，界面展示文件差异与命令输出。编程启用后自主执行，目录不是沙箱，已发生的文件修改不会因停止任务自动回滚。

用户还可以按需启用公开搜索、天气和受信任的只读 MCP 服务。外部信息与个人记忆分别引用，网页和桌宠共用工具配置。本机编程与应用内业务修改采用不同授权方式，记忆和工作对象的修改仍须用户确认。

## 三、技术方案与实现思路

### 1. 总体架构

作品采用“原生采集端 + Python 业务服务 + 本地数据存储 + 内置智能体 + Web/桌宠交互”的架构。业务数据与状态以 PostgreSQL 为准，记忆框架负责提供检索候选，Pi 负责组织模型与工具调用，各层通过明确接口协作。

| 技术层 | 主要技术 | 实现职责 |
| --- | --- | --- |
| 原生客户端 | Swift、AppKit、WKWebView | 窗口定位、截图采样、采集状态、桌宠窗口与聊天容器 |
| 文字识别 | PaddleOCR、PP-OCRv6 tiny 检测与识别模型 | 在本机将窗口画面转换为文字 |
| 业务服务 | Python 3.12、FastAPI、SQLAlchemy 2、asyncpg | 数据接收、去重、来源校验、任务调度和业务操作 |
| 数据存储 | 原生 PostgreSQL 17、Alembic | 保存原文、记忆、项目、会话、提醒、任务与版本依赖 |
| 记忆检索 | 默认 ReMe，可选 Graphiti + Neo4j | 管理记忆索引，提供相关内容候选 |
| 模型服务 | 默认 Ollama，也支持 OpenAI 兼容生成服务 | 原文选择、问答、报告草稿、代码任务和上下文压缩 |
| 智能体与工具 | 完整 Pi Coding Agent SDK、MCP | 按需检索、工具调用、编程执行与操作提案 |
| 网页界面 | React、TypeScript、Vite | 时间线、项目空间、聊天、回顾、提醒与偏好设置 |

### 2. 从窗口采样到可检索记录

采集端首先检查用户同意、运行选择、系统权限、排除规则和安全输入状态，满足条件后获取当前窗口画面。辅助功能接口主要用于定位窗口与检查上下文，正文由 PaddleOCR 识别。

OCR 串行执行，上一轮未完成时跳过新采样。识别文字进入有容量上限的本地文件队列，收到后端入库或过滤确认后才移除；事件 ID 用于保证上传重试不会重复写入。队列满时暂停新采样，继续上传已有文字。

后端使用仍然有效的数据库记录作为去重基准，默认相似度阈值为 95%，并单独检查关键数字、状态与句子变化。去重跨越五分钟归档片段，静止页面不会因时间段切换反复创建新任务。

有效原文与待处理任务在同一事务内提交，原文入库后建立全文检索能力。后台任务将原文划分为带上下文的来源块，模型只返回所选块的 ID；后端核验哈希、偏移和版本后保存对应原句，并通过记忆框架公开接口更新索引。

整体数据路径为：

```text
允许采集的当前窗口
    → 本机 OCR
    → 文字队列与重试
    → 过滤、去重与 PostgreSQL 入库
    → 模型选择来源块，后端还原原句
    → 记忆索引与后续查询
```

### 3. 记忆检索与智能体问答

Python 托管 Pi 的 Node 子进程，将当前问题、有效会话历史和工具能力交给内置智能体。Pi 根据问题决定直接回答，或通过本机 MCP 调用记忆检索、项目查询、日期记录和对象工具。

检索融合记忆后端候选与 PostgreSQL 全文结果，并按日期、项目等条件筛选。候选必须回到业务数据库核验删除状态、保留期和来源版本，之后才交给模型。最终回答再检查引用是否来自实际提供的有效材料，并保存本轮使用内容的来源依赖。

长对话使用 Pi 的自动或手动上下文压缩，原生会话条目、压缩边界和工具记录存入 PostgreSQL。压缩服务于当前对话的持续执行，不自动转化为长期个人记忆。

默认生成模型为 `qwen3:8b`，本地嵌入模型为 `qwen3-embedding:0.6b`。生成请求统一经过 Python 调度器，待执行的交互问答优先于后台整理。用户可以验证并保存局域网或云端生成服务；选择远程生成时，相关工作文字、会话和代码上下文会发送到该服务，OCR 与嵌入保持本机处理。

### 4. 共享交互与操作确认

网页和桌宠复用聊天组件及同一组会话 API，通过无正文的状态通知获取更新，再读取经过认证的当前数据。因此，两个入口能够共享回答、提醒、停止操作和确认卡片。

应用内修改采用“提出预览—用户确认—事务执行”流程。提案保存目标快照、对象版本、来源依赖和到期时间；确认时重新核验，版本变化则要求重新预览。批量操作固定当时的目标，后续新增对象不加入旧清单，事务失败整体回滚，重复确认只执行一次。

提醒由独立持久调度器按计划时间触发，不依赖模型即时生成。主动陪伴则走共享 Pi 和后台生成队列，展示前检查安静时段、桌宠可见性、交互状态与结果有效期，模型忙或错过机会时跳过。

### 5. 来源一致性与持续运行保障

记录、确认记忆、回答、报告和操作提案之间保存来源版本关系。原文被纠正、删除或到期后，系统沿依赖关系清理或失效相关内容。主动纠正会使关联确认记忆进入待核对状态；原文自然到期则保留独立确认记忆。

后台任务使用 PostgreSQL 持久队列，通过租约、续期和版本检查处理重试及并发，避免旧任务覆盖新结果。记忆后端离线时采用后端级冷却，来源有效性检查持续生效。

管理入口提供安装修复、状态诊断和备份。数据库备份使用 `pg_dump`，恢复验证在独立临时库中进行；采集诊断分别显示截图、OCR、上传和实际入库阶段，便于定位具体问题。

## 四、作品创新点

### 1. 将工作线索采集与个人记忆使用连接起来

作品把窗口文字采集、时间线回看、自然语言检索、项目上下文恢复和报告整理整合为连续流程。记录保留时间、应用和来源关系，用户可以从一段回答返回原文，再把核对后的内容用于后续工作。这种整合使零散的屏幕文字具有可追溯、可继续使用的价值。

### 2. 采用“原文摘录—用户确认”的分层记忆机制

自动整理只选择来源块并还原原句，长期记忆由用户编辑和确认，成果草稿使用确认材料。该机制针对屏幕记录容易混入计划、示例和第三方内容的问题，明确区分“出现过的文字”和“本人认可的事实”，降低自动整理将推测固化为个人记忆的风险。

### 3. 让删除和纠正覆盖派生内容

来源依赖覆盖回答、报告、提案、Pi 上下文和陪伴内容。原始信息变化后，相关派生内容同步清理或失效，检索候选也必须回到当前业务数据核验。通过版本依赖、删除标记和在途结果检查，减少旧记忆被后台重试、旧索引或历史上下文重新带回的情况。

### 4. 面向持续采集的跨片段去重与重要变化保护

去重依据持久化到数据库，并跨越时间片段比较有效基准，减少静止页面反复产生记录和模型任务。同时保护数字、否定、完成状态和新增内容，兼顾重复过滤与关键信息保留。结合 OCR 忙碌跳过、有限队列和上传幂等，使持续采样更适合个人电脑的运行条件。

### 5. 将桌宠交互接入同一套记忆与任务系统

桌宠直接共享网页中的会话、记忆、任务和操作状态，支持从轻量交流进入正式管理。主动陪伴结合模型生成、用户明确反馈和可展示状态控制，在提供个性化形象与交流体验的同时，保持与正式提醒、数据采集和编程授权的边界。

### 6. 为自然语言操作提供可核对的执行机制

模型负责理解需求和生成提案，用户通过具体卡片确认业务修改，后端通过事务与版本重核保证操作范围。批量操作采用固定目标清单，支持一次确认并避免波及后来新增对象。该设计让自然语言能够承担实际管理入口，同时保留目标可见、结果可查和重复执行可控的操作过程。
