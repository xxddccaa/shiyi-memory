# 日常对话回归评测

这套程序模拟普通用户给拾忆安排任务，通过实际 Pi、业务 MCP 工具、认证聊天与确认接口执行，再核验数据并交给独立模型评审。它用于回答“这些日常任务有没有被改坏”，不以助手说“完成了”作为完成证据。

## 运行

在项目根目录运行。需要已安装的 Pi、项目 PostgreSQL、本机嵌入服务及可用的生成服务；程序不会自动启动、重建或重新签名原生应用，也不自动下载模型。

```bash
# 查看任务，无数据库或模型请求
uv run python scripts/evaluate_dialogues.py --suite full --list

# 12 条核心任务，每条使用第一种固定说法
uv run python scripts/evaluate_dialogues.py --suite smoke

# 完整话语库：66 个任务 × 3 种说法 = 198 条
uv run python scripts/evaluate_dialogues.py --suite full

# 核心集重复三遍，保留每一次结果
uv run python scripts/evaluate_dialogues.py --suite smoke --repeat 3

# 按失败 ID 复现；不指定 variant 时运行该任务的三种说法
uv run python scripts/evaluate_dialogues.py --case todo-delete-context --variant 2

# 对比已有 JSON 报告；相对路径从项目根解析
uv run python scripts/evaluate_dialogues.py --suite full --baseline data/exports/dialogue-evals/<run-id>/report.json
```

被测 Pi 始终使用当前保存的模型配置。模拟用户和评审默认使用当前配置中的 27B；若被测模型不是 27B，默认请求同一服务上的 `Qwen3.8-27B`，也可用 `--role-model` 指定服务实际提供的模型 ID。两类请求都走测试应用的共享生成调度器，模型之间不共享对话上下文。不会切换服务、继承其他地址的凭据、修改正式配置或静默回退；服务不提供该评审模型时属于评测未完成。

每条默认最多 32 次用户消息／32 次单阶段决策、20 分钟，使用 `--max-turns`、`--timeout` 调整。这些仅是测试程序的终止条件，不修改产品的模型／工具额度。连续 12 次完全相同的工具、参数和结果，或 2–4 步工具序列重复至少六轮且不少于 12 次调用，会被识别为无进展循环。程序取消当前运行并记录行为失败；分页游标、目标或结果有变化时不算相同循环。

## 任务和话语

固定用例在 `backend/workmemory/evaluation/scenarios.py`。每个任务有固定 ID、三种开场说法、合成初始状态、阶段目标、允许确认的范围和状态断言。后续追问由模型根据真实回复产生；单轮澄清任务设置 `allow_followups=false`，模型只评判助手是否正确追问，不替原任务补出时间。模拟用户不能读取数据库答案、向 Pi 传内部工具指令或替它改参数。固定数据中的对象 ID 在同一任务的不同说法与重复运行间保持一致；会话、运行和提案仍由真实业务生成。

| 类型 | 覆盖 |
|---|---|
| 待办 | 创建、查找、项目/完成状态筛选、改名、改时间、暂停/恢复日程、完成/恢复、忽略、删除、合并 |
| 定时提醒 | 每天、周一至周五、指定星期、缺少时间先询问、采集计划不自动创建、本次完成、延后10分钟、恢复提醒 |
| 批量 | 69 条、105 条、按项目/完成状态删除、确认后新增目标保护 |
| 多轮 | 创建→改时间→查询→删除→再查；指代、同名澄清、多意图、反悔后换操作 |
| 记忆 | 创建/确认、查询、更正、忘记、拒绝、压缩后忘记和跨会话追问 |
| 工作 | 今日/昨日、无记录、仍在整理、真实合成文字入库到 ReMe 索引、片段纠正/删除/移动、工作段编辑 |
| 项目和回顾 | 项目概况、别名、合并、单个/32个项目一次确认删除、人工回顾保存 |
| 普通对话 | 问模型、问候、一般知识、建议、工作回顾与建议混合、未支持的外部操作 |
| 一致性 | 过期卡片、版本变化、重复确认、消息幂等、取消、连接故障后的重试、共享会话继续 |

覆盖全部 19 种已提供的业务提案动作；项目删除解除分类归属，保留工作记录、待办和确认记忆，外部写操作仍不在范围内。新增记忆兼容实际界面的两种路径：Pi 操作卡片，以及“从这次对话记住什么”中的候选卡片；有 Pi 提案时优先使用提案。其他任务产生的候选草稿不自动确认。

Web/桌宠用例验证同一会话接口和状态可继续使用。它不是浏览器像素、输入法、AppKit 动画或原生窗口验收；已有浏览器和 Swift 检查仍然保留。编程、外部 MCP、Graphiti 与真实桌面 OCR 不在这套首版评测中。

## 如何判定

1. 模拟用户只能发送话语、确认授权范围内的可见卡片、拒绝或结束。错误目标/参数的业务卡片会被拒绝并记失败。重复提交原值不算额外修改，但未请求的变化不能确认。
2. 程序在发送、追问、确认和各阶段结束时读取数据库快照，核验目标内容/时间/状态、数量和未授权对象。候选草稿与已确认记忆分开处理。自动回顾的新建/刷新只在本轮确实成功调用 `get_work_day(prepare_report=true)`、日期匹配时视为允许的派生更新；人工正文和编辑版本仍必须经过确认，既往工具调用不能授权后续写入。
3. 更正、删除和相关修改之前记录来源依赖；确认后立即检查回答、报告、Pi 会话及工具正文是否失效，先检查再读取 UI，避免被读接口的补救清理掩盖缺陷。
4. 27B 独立评审任务、对话、卡片、工具轨迹和真实数据。检查理解、完整性、依据、虚报成功和澄清质量；被评内容中的指令只是数据。程序提供 `time_context`，将带偏移的证据时间换算到配置时区，避免把 UTC 日期直接当本地日期；原始证据仍保留，时间换算不能覆盖授权、来源或其他失败断言。
5. 硬断言和语义评审同时通过才是通过。评审不能推翻硬失败；模型故障、评审格式错误、模拟器违反协议、超时、跨本地午夜等记为未完成。Pi 输出错误格式、缺卡片、循环或办错任务属于产品行为失败。

长会话用例会发送足以越过当前 Pi 保留窗口的合成历史，调用真实压缩，并核验实际产生了压缩条目；不会下调正式上下文配置，长会话用例的模型输入和耗时明显高于普通事务。

过期、目标版本变化、新增目标和一次模型连接故障由明确记录的测试故障注入产生，不冒充普通用户动作。连接故障后的下一次请求仍使用真实模型。初始记录可由夹具建立；标注 `pipeline` 的用例则必须通过 `/api/ingest`、实际持久任务处理函数、真实嵌入和 ReMe 公共接口完成入库与索引，核验任务状态、回执和实际搜索结果。测试不使用 `FakeRegistry`；只有评测系统自身的确定性单元/集成测试使用模型替身。

## 报告与隔离

输出目录为 `data/exports/dialogue-evals/<日期-随机ID>/`，由 Git 忽略：

- `report.html`：本地直接打开，按结果筛选、搜索，查看阶段对话、操作决定、数据差异和完整证据。
- `report.json`：机器可读的覆盖、全部尝试、耗时、模型调用数、判定与历史对比。
- `<任务>-v<话语>-r<轮次>.json`：执行中的检查点；中断不会把已有结果丢掉或变成通过。

报告记录代码指纹、评测器/用例/提示词指纹、实际模型参数、选择范围、时区和时间基准。配置或用例/评测规则不同的报告列为不可直接比较；没有运行的用例不算通过。不以多次复测后的最后一次结果覆盖早先失败。

退出码：`0` 全部选定用例通过；`1` 存在行为失败；`2` 环境/评测未完成或还有计划用例未运行。失败和未完成并存时为 `2`。

每次评测创建随机命名的 `workmemory_eval_*` PostgreSQL，应用迁移后逐用例清空这个自建库。删除/清空前核验数据库所有权，绝不把正式库作为测试目标。每条用例拥有独立 ReMe 工作目录、认证令牌和关闭外部服务的 MCP 配置。退出后关闭 Pi 和模型工作、删除临时库与工作目录，报告保留；SIGINT/SIGTERM 走清理流程，系统断电或 SIGKILL 无法保证立即清理。

程序只对正式配置与原生二进制取指纹，模型密钥不进入报告、Node 或前端。合成对话可能发送到用户选定的生成服务。工作日工具仍会返回本机不含正文的采集心跳（如权限状态和最近采集时间）；业务记录来自独立测试库，心跳不用于证明合成任务完成。报告中的“保护文件未变”说明配置/二进制指纹一致；不能把它当作真实桌面采集或系统权限验收。

## 增补日常用法

先把发现的问题收敛成独立任务，再加入 `scenarios.py` 的 `library()`：

1. 使用稳定的任务 ID，写三种用户真实会说的开场话；同一任务的三种说法应具有相同目标。多步流程拆成 `stages`，每阶段明确完成条件。
2. 用 `seed` 建立最小合成状态，并至少保留一个不能误改的对象。新增夹具在 `environment.seed()` 中定义，不读取正式记录作为样本。
3. 修改任务声明 `Permit`：目标、时间、项目和状态用精确值，语义上允许改写的正文才用 `text_contains`。创建后的 ID 通过 `bind` 留给下一阶段；不能让评审模型替任务扩充授权范围。
4. 用 `Check` 核验真实状态。查询任务由独立评审对照夹具和结果判断，必要时要求确实调用工作日或记忆工具。涉及删除、更正时，加入同会话及新会话追问。
5. 先单独运行该任务的全部说法，再纳入完整集。核心集维持固定规模；要替换核心任务时同步调整覆盖测试和文档。

用例内容、模拟器提示和判定逻辑均有指纹。改了话语或验收标准后，不应把新结果直接当成旧版本产品改善；报告会标记这种基线不可直接比较。真实模型的失败修复后，应使用同一批话语和重复次数再次评测，并保留修复前报告。

## 修改评测器后的验证

```bash
uv run pytest -q tests/unit/test_dialogue_evaluation.py tests/integration/test_dialogue_runner.py
uv run ruff check backend scripts tests
```

反向测试故意让模型评审全部给通过，仍要求无实际写入、错目标、误改其他对象、缺少来源清理不能通过；同时验证正常 API 确认、候选记忆确认和明确请求的自动回顾刷新不会被误报；自动刷新不能冒充人工回顾保存成功。真实模型记录及已发现的产品回归见 `docs/verification.md`。

## 2026-10-10 实测后的产品修复顺序

2026-10-10 首轮完整话语库揭示了以下问题，当日交付仅增加评测器。2026-10-11 至 2026-10-12 已按下表实施产品修复，随后补充名称合并、最新更正回执和最终回答提交协议；原始失败报告保留，新一轮的实际通过情况见 [验证记录](verification.md)。修复后使用同一批话语复测，再检查核心集及完整集，不能将未运行的任务计为通过。

| 顺序 | 问题与复现任务 | 已实施改动与验收目标 |
|---|---|---|
| 1 | `project-merge` 三种说法均把保留/并入目标写反 | 工具 Schema 明确 `target_id` 为保留项目、`other_id` 为被合并项目，卡片明确显示方向。核验星河进入蓝鲸、蓝鲸保留，来源及待办随目标正确迁移。 |
| 2 | `todo-rename` 三种均把“未完成”展示后缀带进标题；`todo-clear-due`、`todo-reopen` 部分话语附带改名 | 业务查询返回独立的原始标题、状态和展示文本；提案只提交用户要求变更的字段。分别核验精确标题、`due_at=null`、完成状态及未请求字段不变。 |
| 3 | `session-update`、`review-save` 无法定位可操作目标 | 补齐工作段和回顾的列表/详情工具及稳定 ID、版本、日期定位；工作段增加独立编辑版本，回顾覆盖真实网页入口；分清工作段、原始片段、自动报告与人工正文。核验真正生成对应操作卡片并在确认后写入目标表，不能改片段摘要代替工作段改名。 |
| 4 | `todo-chain`、`todo-missing`、`chat-greeting`、`chat-knowledge` 偶发 `invalid_answer`；`memory-update` 后追问出现 `invalid_citation` | 最终结构与未知引用共用一次带 Schema 的修复；需要新证据时保留工具，并在 Pi 保存前及正式发布前校验。不以固定兜底文案或取消引用校验来掩盖错误；同一任务多次测试应保留全部结果。 |
| 5 | `todo-ambiguous`、`work-yesterday`、`todo-multi-intent` 重复工具无进展；`todo-merge` 某种说法理解偏差 | 工具返回项目名与同名匹配提示；澄清要结束本轮，不为每个候选生成卡片。稳定重复查询提示完成或澄清；待办/项目读取不再伪造采集时间。验证分页仍能前进、不会在两个同名目标之间循环，也不会把“并到另一条”当作撰写周报。 |

全部通过只证明所选用例、当时配置和运行环境符合这些断言，不能保证所有自然语言、模型更新或真实桌面行为没有缺陷。新发现的日常用法继续加入固定任务库，而不是只把失败样本重跑到偶然通过。
