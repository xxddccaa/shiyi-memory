# 普通用户的安装与管理

双击项目根目录的 **拾忆管理.command**。第一次选择“1 安装／修复”；以后选择“2 启动全部”即可。管理窗口关闭不会停止后台服务，停止服务请选“3”。

首版支持 Apple Silicon 和 macOS 14 及以上。脚本检查开发工具、uv、Python 3.12、Node、Homebrew PostgreSQL 17，再准备原生 Ollama、Qwen 生成／嵌入模型、PaddleOCR tiny、网页和菜单栏应用。现有可用依赖直接复用。缺少的 uv、Python 和 Node 安装在项目 `.tools/` 内，不修改 shell 配置。默认 ReMe 不需要 Docker Desktop；选用 Graphiti/Neo4j 或迁移旧 Docker 数据时才需要现有 Docker。

macOS 的开发工具安装、Homebrew 首次安装和采集权限需要本人在系统界面完成。脚本会解释当前环节；中断后重新选择“安装／修复”。下载可续传，模型及已构建成果经过检查后复用。安装记录保存在 `.run/installation.json`，当前步骤在 `.run/install-state.json`，运行日志在 `logs/`。

## 菜单和命令

| 菜单 | 命令 | 作用 |
|---|---|---|
| 安装／修复 | `bash scripts/manage.sh install` | 补齐依赖、配置、数据库迁移、模型和构建成果 |
| 启动全部 | `bash scripts/manage.sh start` | 检查已有安装，启动数据库与本机进程、采集端和网页 |
| 停止全部 | `bash scripts/manage.sh stop` | 先退出采集端，再停本项目 API、OCR、Ollama 和数据库 |
| 重启 | `bash scripts/manage.sh restart` | 停止并按依赖顺序启动 |
| 查看状态 | `bash scripts/manage.sh status` | 中文服务、模型、权限和队列状态 |
| 诊断 | `bash scripts/manage.sh doctor` | 缺少依赖、权限和服务的处理建议 |
| 日志 | `bash scripts/manage.sh logs` | 最近运行日志 |
| 备份 | `bash scripts/manage.sh backup` | `pg_dump` 归档到 `data/backups/` |
| 卸载 | `bash scripts/manage.sh uninstall` | 移除运行组件，保留全部数据、配置、模型与备份 |
| 重新授权拾忆 | 双击 `修复拾忆权限.command` 或 `bash scripts/manage.sh permissions --guided` | 清除本应用旧授权，逐项引导系统授权并核验新进程 |
| 彻底清除 | `bash scripts/manage.sh purge` | 输入“清除拾忆全部数据”确认后清除项目数据 |

`status --json` 给其他程序使用；`start --no-open` 不打开网页；`start --graphiti` 启动可选 Neo4j。网页切换过的记忆后端以 PostgreSQL 中的选择为准。旧 `bootstrap.sh`、`dev-up.sh`、`dev-down.sh` 分别转到安装、启动和停止。

普通启动不会安装依赖、下载模型、编译或重新签名。修改源代码或需要补装本地模型时选择安装／修复。网页中的生成模型设置在验证并保存后即时生效，无需安装／修复或重新授权。它只在源码指纹变化或产物缺失时构建。开发者仍可独立运行原有下载、备份和验证脚本。

停止后端时，网页事件和本机 MCP 长连接最多等待10秒后结束，再执行后台任务及模型资源清理；总退出时间还包含清理过程。管理器仍核验进程归属，超出正常停止窗口会报告未退出，不自动强杀或接管其他服务。

## 原生 PostgreSQL 与旧数据迁移

PostgreSQL 17 的程序来自 `brew install postgresql@17`。管理器以当前用户运行 `pg_ctl`，只管理本项目 `data/postgres-native`，不创建系统服务或全局开机启动项。普通启动复用实例；备份和恢复检查均使用原生 `pg_dump`/`pg_restore`。默认 ReMe 下 Docker 可以保持关闭；其他项目或选用的 Neo4j 仍可能需要它，管理器不会自动退出全局 Docker Desktop。

已存在 `data/postgres/PG_VERSION` 时，安装/修复会先停止本项目写入，再临时启动旧容器导出。先在独立临时库验证备份可恢复，再恢复到项目原生库，并核对全部业务表的 SHA-256 内容摘要、条数、序列和列定义。成功后原子保存 `config/database.local.json`，保留旧容器数据和 `data/backups/docker-migration-*.dump`。目标非空且内容不同会拒绝覆盖；失败时检查 `logs/postgres.log` 与迁移提示，不删除旧目录来强行继续。

仅迁移数据库、不重建原生界面的开发者操作：先关闭采集端并停止本项目后端，再运行 `uv run python scripts/migrate_postgres.py`、`uv run alembic upgrade head`，最后从管理入口启动。迁移命令不会修改模型配置或采集选择。数据库结构更新后，应再次备份并执行 `bash scripts/restore-check.sh 备份路径`。

如要回到迁移前状态，先停止本项目采集端、后端和原生数据库，保留原生目录与部署标记副本，再使用与旧库结构匹配的代码启动旧容器。旧目录只含迁移时数据；迁移后产生的数据需要另做逻辑备份，不能直接覆盖旧库或物理混用两种数据库目录。

`uv run python scripts/verify_infra.py` 只在临时实例验证重启与备份恢复，不停止业务数据库、不改变用户采集选择。卸载默认保留原生数据和迁移记录，重新安装可接回；彻底清除时必须先确认项目原生实例及仍保留的旧容器均已停止，不卸载共享 Homebrew 或 Docker。

## 网页模型设置

在网页“偏好与状态 → 整理与问答模型”填写服务类型、地址、模型名和可选 API Key，先测试，再验证并保存。嵌入检索与 PaddleOCR 继续在本机运行。配置在重启后保留，默认卸载也保留。详细字段与操作见 [模型配置指南](models.md)。

管理器会按已保存的生成配置检查模型。选择远程服务后，本机 Ollama 只要求嵌入模型；状态页另行显示远程生成服务，不会因为缺少未使用的本地生成模型而误报。

## 采集权限

1. 在叶子菜单点击“授予辅助功能权限”，允许 `macos/WorkMemory.app`。
2. 点击“授予屏幕录制权限”，按系统提示允许；要求重开时按提示操作。
3. 默认每五秒单张 OCR，无需输入监控权限。只有手动选择 `capture_mode: interaction` 时才需要“授予输入监控权限（操作触发）”。
4. 首次点击“开始采集”并同意文字采集。以后启动会恢复上次选择；手动暂停会保持暂停。

应用使用本机构建的临时签名。**更新二进制后，macOS 可能要求重新授权**，即使设置页仍显示旧开关为开启。如果需要重新添加，在系统设置中移除该旧条目，把当前 `macos/WorkMemory.app` 拖入对应列表再打开开关。普通安装、修复和启动不会重置 TCC 权限，也不会弱化签名要求。旧条目反复授权无效时，可双击根目录 `修复拾忆权限.command`，或主动选择菜单“11 重新授权拾忆”。脚本仅清除 `local.workmemory.collector` 当前模式所需的旧授权：默认定时 OCR 为辅助功能和屏幕录制，只有操作触发模式才清除输入监控，显式关闭 OCR 时不要求屏幕录制。

修复脚本不需要 `sudo`，也不接收或保存管理员密码。macOS 的 `tccutil` 支持重置旧决定，不提供静默授予这两项权限的命令；最终授权仍由你在系统界面点击，系统如要求解锁，密码只在 macOS 弹窗里输入。脚本会打开 Finder 并选中当前应用，逐项打开设置；添加当前应用、开启权限后回到终端按回车。若旧条目仍在，先移除再添加，而不是反复切换同一个旧开关。没有添加按钮时，从拾忆菜单点击对应的“授予…权限”。

完成系统操作后，脚本自动重开当前应用，检查新 PID 的新鲜心跳与当前二进制指纹，最多用30秒核验权限、截图/OCR及新增入库元数据。请切到普通工作窗口，避免修复终端本身命中排除规则。用户原先暂停或未开始时保留该选择，不会为了测试而开启采集。结果保存到 `.run/permissions-result.json`，区分权限生效、实际采集和入库未确认；没有新鲜心跳或权限仍失效时返回失败。过程中不构建、不重新签名、不修改 TCC 数据库，也不停止数据库、模型或后端。普通启动和安装不会调用此授权流程。

“进程运行”与“正在采集”分别显示。缺少权限、锁屏、处于排除窗口时不记录内容；OCR 就绪本身不能证明屏幕采集正常。默认不开机自启。

## 卸载边界

MCP 设置在“偏好与状态 → 联网与工具”保存后由后续调用使用，无需重新构建或签名；搜索和天气默认关闭，设置中的访问凭据不会返回给网页。

默认卸载保留 `data/`、`models/`、本地配置、凭据及备份，留下源码和双击入口，重新安装可以接回原有记录。彻底清除也会删除备份、生成服务配置与 MCP 服务配置/凭据，因此只在确定不再需要历史时使用。

停止和卸载只处理本项目进程及绑定本目录的容器。发现其他目录的同名容器或外部符号链接时拒绝处理。共享 Docker Desktop、系统开发工具、其他项目服务不会被卸载。数据库无法确认停止时，拒绝彻底清除。

## 桌宠与本轮升级

单击桌宠现在负责开关聊天。PNG 形象可从网页“偏好与状态 → 桌宠形象”或原生右键菜单导入，统一存放在 `data/collector/desktop-pets/`，单图动效在两端共享。更换形象不需要安装/修复、不重新编译或签名；首次安装这项原生代码更新仍需按下述权限规则验收。

安装/修复会构建同一 WorkMemory 应用内的原生桌宠，普通启动不构建。菜单栏可聊天或显示/隐藏桌宠，Web 偏好页也能修改；聊天不改变采集同意或暂停选择。模型与对话由应用内 Pi 共享，不需安装 Pi CLI、OpenCode 或独立桌宠框架。详见 [个人版说明](personal-companion.md)。

升级前后使用 `scripts/backup.sh` 和 `scripts/restore-check.sh` 验证数据库备份。当前迁移到 `f13a8_optimization`，增加独立确认记忆、维护任务与采集诊断事件，前序 `e02f7_evidence_policy` 增加保守原文策略；`d91f6_proactive` 新增短期主动陪伴记录；前序 `c83e5_scheduled_todos` 增加日程及持久提醒实例；该迁移只改变结构，不自行删除数据。前序 `b72d4_session_edit` 为工作段增加独立人工编辑版本；前序 `a14b3_pi_sdk` 新增 Pi 原生会话检查点、目录与扩展设置、工具执行日志和命令输出；前序 `f03a2_mcp` 保存外部来源、对象上下文和待办删除标记，直接降级会丢失这些语义，应优先使用与旧代码对应的升级前备份。如已创建无来源片段的独立待办，旧表结构无法表示这些记录，降级会拒绝；应保留增量结构，或在停止后端后恢复明确选择的旧备份。

数据库备份包含共享偏好、会话、确认记忆、提案、反馈和报告。迁移机器还应安全转移 `config/app.local.yaml`、`config/secrets.env`、`config/generation.local.json`、`config/mcp.local.json` 及 `data/collector/`（含采集同意、文本队列、宠物皮肤与位置）；这些文件不提交 Git。重新安装生成路径相关配置并重新授予 macOS 权限，不能复制旧的 TCC 授权作为新机授权。不要从运行中直接复制 `data/postgres-native/` 或旧 `data/postgres/`。原生归属记录 `config/database.local.json` 包含本机路径，迁移机器需重新初始化目标实例并恢复 pg_dump，不能直接复制归属标记接管。

## Agent 调用额度

`config/app.local.yaml` 可以通过 `agent` 节覆盖调用次数、工具资料累计字符数、上下文目标字符数与整轮超时，字段及当前默认值见 `config/app.example.yaml`。已有配置未写此节时由后端自动采用默认值，不重写采集选择或 Swift 派生配置。修改后重启后端生效，无需重装/重新签名原生应用。默认额度很高，表示最多允许执行多少次，不表示会主动消耗这些调用；模型上下文大小和单请求连接超时仍独立处理。

## 完整 Pi SDK 升级

Agent 依赖由 `agent/package-lock.json` 锁定；管理器根据 `package.json`、锁文件、`worker.mjs`、`session.mjs` 的指纹检查和安装。升级仅涉及 Python、Node 与网页时，可先备份并完成独立恢复检查，再停止本项目 backend、执行 `uv run alembic upgrade head`、启动 backend。无需重新构建或签名 Swift；不改采集同意和暂停状态。不要在运行中的业务库上做清空或降级试验。

数据库备份现在也包含 Pi 会话、压缩摘要与执行日志。项目文件不包含在 PostgreSQL 备份内，需要项目自己的版本管理/备份；目录登记迁移机器后要核对路径。编程命令发生中断时显示结果待核实，不能从会话重试按钮重放可能已经写入的操作。

## 保守原文策略升级

迁移 `e02f7_evidence_policy` 增加来源策略、摘录到期时间、原文定位和隔离历史表，并单独记录工作段标题的明确确认。旧自动摘要立即标记待复核；后端接收请求前，在一个事务中保存历史展示内容、清理其活跃派生上下文，并排队清理各已使用的记忆后端。用户纠正、确认记忆及人工字段保留。后台仅从尚存原文渐进复核，不把旧摘要重新送给模型。曾使用但当前未选中的后端仍登记清理任务，调度顺序排在当前后端及原文复核之后，避免离线的可选 Graphiti 积压阻塞默认 ReMe；切换后端后优先级按实际选择重新判断。

本次 Python/网页更新无需构建或签名原生应用。先检查活跃会话，停止本项目 backend 写入，使用 `pg_dump` 备份并执行独立恢复检查，再运行 `uv run alembic upgrade head`，只启动 backend。数据库、OCR、Ollama 和原生应用可继续运行；上传队列会保留未确认文字。原生进程、二进制、模型配置及用户采集选择应核对保持不变。该迁移拒绝降级，避免将隔离内容重新暴露给旧逻辑；恢复需用已验证备份及匹配代码，不能覆盖运行中的业务库做试验。

网页首页的采集状态区分进程离线、暂停、锁屏、权限失效、链路错误、待上传、重复过滤和最近截图活动。展开后分别看截图、OCR、收到上传与入库记录的采集时间，旧队列上报不等于发生了新截图。权限仍未生效时必须由本人在系统界面为当前 `macos/WorkMemory.app` 授权，不能用后端健康或自动整理通过替代实采验收。

## 备份维护与原生更新

网页“偏好与状态 → 备份与维护”提供自动备份开关、立即备份、归档列表和独立恢复验证。默认应用时区03:00备份，停机后只补最近一次；保留最近7个备份日和4个备份周，手动/升级备份单独保留。恢复验证在临时库检查全部公共表与约束，不替换当前数据库。调度、中断恢复及后端冷却规则见 [本轮优化说明](optimization.md)。

原生构建先在项目内暂存并完成签名验证，再退出旧采集端、替换应用。`.run/native-update.json` 保存更新前后签名、二进制摘要及采集选择；`.run/previous-WorkMemory.app` 保留上一版。只改皮肤无需原生更新。

有稳定的本机代码签名身份时，可在忽略的 `config/signing.local.json` 设置 `{"identity":"签名身份名称或指纹"}`，仅由安装/修复时的原生构建采用。身份来自本机钥匙串，程序不索取密码。缺省仍使用 ad-hoc 临时签名，并明确告知可能需要重新授权；不重置 TCC，也不降低签名验证。切换为稳定身份本身可能需要首次重新授权。

更新后的真实采集验收必须核对新进程的截图、OCR及 PostgreSQL 入库；旧的运行记录不能作为本次成功证据。权限未生效时，网页提供系统设置、定位当前应用和仅重开本项目应用的入口；保留暂停选择。稳定证书签发、干净机器安装与长时间实采仍须对应环境验证。
